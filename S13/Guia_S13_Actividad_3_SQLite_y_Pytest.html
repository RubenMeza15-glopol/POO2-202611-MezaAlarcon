4. Actividad 3 — RepositorioSQLite y prueba de sustitución

30 minutos

¿Qué hace SQLite?

SQLite es una base de datos ligera que se guarda en un archivo, por ejemplo estudiantes.db. A diferencia de JSON y CSV, almacena los datos en una tabla y permite consultarlos con SQL. Python incluye el módulo sqlite3, por lo que no hace falta instalar un servidor de base de datos.

Archivo: repositorio_sqlite.py — código comentado

import sqlite3                       # Permite conectarse y ejecutar sentencias SQL en SQLite.
import json                          # Convierte la lista de notas a texto y de vuelta.
from typing import Optional          # Permite indicar que buscar puede devolver None.
from estudiante import Estudiante    # Importa el modelo Estudiante.

CREATE_SQL = (                        # Define la sentencia SQL para crear la tabla.
    "CREATE TABLE IF NOT EXISTS estudiante(" # Crea la tabla solo si todavía no existe.
    " codigo INTEGER PRIMARY KEY,"    # Código entero que identifica de forma única al estudiante.
    " nombre TEXT NOT NULL,"          # Nombre obligatorio almacenado como texto.
    " ppa REAL NOT NULL DEFAULT 0,"   # PPA decimal obligatorio, con valor inicial 0.
    " notas TEXT NOT NULL DEFAULT '[]')" # Notas almacenadas como texto; por defecto lista vacía.
)                                     # Termina la definición de la sentencia SQL.

class RepositorioSQLite:              # Declara el repositorio basado en SQLite.

    def __init__(self, ruta: str) -> None: # Constructor: recibe el archivo de base de datos.
        self._con = sqlite3.connect(ruta, # Abre o crea la base de datos indicada.
                                    check_same_thread=False) # Permite usar la conexión desde otros hilos.
        self._con.execute(CREATE_SQL) # Crea la tabla si aún no existe.
        self._con.commit()            # Confirma los cambios de creación de la tabla.

    def guardar(self, e: Estudiante) -> None: # Inserta o reemplaza un estudiante.
        self._con.execute(            # Ejecuta una sentencia SQL parametrizada.
            "INSERT OR REPLACE INTO " # Inserta; si la clave ya existe, reemplaza el registro.
            "estudiante VALUES(?,?,?,?)", # Los cuatro signos ? reciben valores seguros.
            (e.codigo, e.nombre, e.ppa, # Envía código, nombre y PPA como parámetros.
             json.dumps(e.notas)))     # Convierte las notas a texto JSON para guardarlas.
        self._con.commit()             # Confirma la escritura en la base de datos.

    def buscar(self, cod: int) -> Optional[Estudiante]: # Busca por código.
        row = self._con.execute(       # Ejecuta una consulta SQL.
            "SELECT * FROM estudiante " # Solicita todas las columnas de la tabla.
            "WHERE codigo=?", (cod,)).fetchone() # Filtra por código y obtiene una fila o None.
        if row is None:                # Comprueba si la consulta no encontró registros.
            return None                # Informa que no existe ese estudiante.
        return Estudiante(             # Reconstruye un objeto Estudiante desde la fila.
            row[0], row[1], row[2],    # Recupera código, nombre y PPA.
            json.loads(row[3]))        # Convierte la columna de notas en una lista.

    def listar(self) -> list[Estudiante]: # Recupera todos los estudiantes.
        rows = self._con.execute(      # Ejecuta la consulta para obtener todos los registros.
            "SELECT * FROM estudiante").fetchall() # Recupera todas las filas.
        return [Estudiante(r[0], r[1], r[2], # Crea un estudiante por cada fila.
                    json.loads(r[3])) for r in rows] # Reconstruye las notas y devuelve la lista.

¿Qué es la prueba de sustitución?

La guía la relaciona con el principio de sustitución de Liskov (LSP). En términos sencillos: si el servicio trabaja con un repositorio que ofrece las operaciones esperadas, podemos cambiar el repositorio concreto por otro sin tener que reescribir la lógica del servicio.

En esta prueba se utiliza el mismo ServicioEstudiante con cuatro repositorios: memoria, JSON, CSV y SQLite. Se verifica que todos puedan registrar dos estudiantes, buscarlos y listarlos.

Archivo: test_repos.py — prueba comentada

import pytest                         # Importa pytest para parametrizar y ejecutar pruebas.
import os                             # Permite comprobar y borrar archivos temporales.
from servicios import ServicioEstudiante # Importa el servicio que usa el repositorio.
from estrategias import PromedioSimple # Importa la estrategia de cálculo del promedio.
from estudiante import Estudiante     # Importa el modelo de estudiante.
from repositorios import (            # Importa las implementaciones de repositorio.
    RepositorioMemoria,               # Repositorio que conserva datos solo en memoria.
    RepositorioJSON,                  # Repositorio que almacena datos en JSON.
    RepositorioCSV,                   # Repositorio que almacena datos en CSV.
    RepositorioSQLite                 # Repositorio que almacena datos en SQLite.
)                                     # Termina la lista de importaciones.

@pytest.mark.parametrize("RepoClass,kwargs,cleanup", [ # Ejecuta la misma prueba con distintos repositorios.
    (RepositorioMemoria, {}, None),   # Caso 1: memoria; no necesita ruta ni limpieza de archivo.
    (RepositorioJSON, {"ruta": "/tmp/t.json"}, "/tmp/t.json"), # Caso 2: JSON y su archivo temporal.
    (RepositorioCSV, {"ruta": "/tmp/t.csv"}, "/tmp/t.csv"), # Caso 3: CSV y su archivo temporal.
    (RepositorioSQLite, {"ruta": "/tmp/t.db"}, "/tmp/t.db"), # Caso 4: SQLite y su archivo temporal.
])                                    # Termina los cuatro casos de prueba.

def test_servicio_con_cualquier_repo(RepoClass, kwargs, cleanup): # Prueba común para cada backend.
    repo = RepoClass(**kwargs)        # Crea el repositorio de la vuelta actual.
    svc = ServicioEstudiante(repo, PromedioSimple()) # Inyecta repositorio y estrategia en el servicio.
    e1 = Estudiante(1001, "Ana", 0.0, [15.0, 18.0, 14.0]) # Prepara a Ana con sus notas.
    e2 = Estudiante(1002, "Juan", 0.0, [10.0, 12.0, 14.0]) # Prepara a Juan con sus notas.
    svc.registrar(e1)                 # El servicio calcula el PPA y guarda a Ana.
    svc.registrar(e2)                 # El servicio calcula el PPA y guarda a Juan.
    assert svc.buscar(1001).nombre == "Ana" # Verifica que puede recuperar a Ana.
    assert svc.buscar(1002) is not None # Verifica que puede recuperar a Juan.
    assert len(repo.listar()) == 2    # Comprueba que hay dos estudiantes.
    if cleanup and os.path.exists(cleanup): # Si hay archivo temporal y existe...
        os.remove(cleanup)            # ...lo elimina para que la prueba no deje residuos.
Detalle de la guía: el fragmento importa las cuatro clases desde repositorios. Ese módulo debe exponer esas clases. La guía no desarrolla en estas páginas el contenido completo de repositorios.py, ni las implementaciones completas de RepositorioMemoria, ServicioEstudiante o PromedioSimple; aquí se explica cómo intervienen en la prueba, sin inventar sus líneas internas.

¿Qué significa pytest.mark.parametrize?

Permite ejecutar una misma función de prueba varias veces, cambiando los datos de entrada. En este caso cambia RepoClass y crea cada backend. Así comprobamos que el servicio se comporta igual con las cuatro implementaciones.

Resultado esperado según la guía: ejecutar pytest test_repos.py -v y obtener 4 tests PASSED. Cada caso representa una implementación de repositorio.

La pregunta clave de la guía: ¿ServicioEstudiante cambió alguna línea?

No debería cambiar. El servicio recibe el repositorio desde fuera (inyección de dependencias) y utiliza sus operaciones comunes. Por eso se puede sustituir el almacenamiento sin modificar la lógica de negocio del servicio.

Preguntas que podrían hacerte

1. ¿Qué es persistencia?

Es conservar los datos fuera de la memoria del programa para recuperarlos después de cerrarlo o reiniciarlo.

2. ¿Qué diferencia hay entre JSON, CSV y SQLite?

JSON guarda datos estructurados; CSV los organiza en filas y columnas; SQLite los guarda en tablas de una base de datos y permite consultarlos con SQL.

3. ¿Por qué el constructor llama a _cargar()?

Para recuperar automáticamente los datos que ya estaban guardados cuando se crea el repositorio.

4. ¿Para qué sirve _persistir()?

Para escribir en el archivo el estado actual del repositorio. Se llama después de guardar o eliminar.

5. ¿Qué hace assert?

Comprueba una condición. Si la condición es falsa, la prueba falla.

6. ¿Qué demuestra crear r1 y luego r2?

Que los datos no dependen únicamente del diccionario de la primera instancia: se escribieron en el archivo y la segunda instancia pudo recuperarlos.

7. ¿Qué es LSP en esta actividad?

Es el principio de sustitución de Liskov: una implementación concreta puede reemplazar a otra cuando respeta el comportamiento esperado por el código que la utiliza.

8. ¿Por qué ServicioEstudiante no cambia?

Porque depende de las operaciones que ofrece el repositorio y no de cómo se guardan internamente los datos.

9. ¿Qué significa 4 tests PASSED?

Que pytest ejecutó satisfactoriamente el mismo escenario con los cuatro repositorios parametrizados.
